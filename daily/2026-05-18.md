### Session (12:25) - Fixed Silent Flush Crash on rate_limit_event

**Context:** Knowledge folder wasn't populating despite hooks being wired; investigated why daily logs were empty.

**Key Exchanges:**
- Diagnosed that `scripts/flush.py` was crashing inside `claude-code-sdk==0.0.25` with `MessageParseError: Unknown message type: rate_limit_event` — the installed SDK predates a new CLI event type.
- Failures were invisible because flush runs detached with stdout/stderr → DEVNULL; every session "succeeded" but appended nothing.
- Confirmed via evidence: `daily/2026-05-13..16.md` all 38 bytes (header only), `scripts/state.json` and `last-flush.json` never created.

**Decisions Made:**
- Applied fixes 2+3: swallow `MessageParseError` on unknown frames AND redirect flush output to `hooks/flush.log` instead of DEVNULL.
- Rejected SDK upgrade as sole fix — patching parser tolerance + visible logging is more robust against future CLI event additions.

**Lessons Learned:**
- Detached background hooks with DEVNULL'd stderr will silently swallow crashes forever — always log to a file even for "fire and forget" subprocesses.
- SDK/CLI version drift surfaces as new message types; parsers should skip unknown frames rather than hard-fail.
- macOS case-insensitive FS quirk: both `Knowledge/` and `knowledge/` appeared in listings though code only references the lowercase path.
- Knowledge index only repopulates after end-of-day `compile.py` (post-6pm), so fixing the daily flush doesn't immediately reflect in `knowledge/index.md`.

- Recommend prompt-side fix (Option A) over schema loosening: mirror CSV prompt's "derive opening from first row, closing from last row, default currency INR" rules into PDF prompt. Keeps strict D02 contract.

**Lessons Learned:**
- `SandboxError.stderr` was caught but discarded — always surface subprocess stderr in error messages, otherwise debugging LLM-generated code is blind.
- Magic-byte detection (`%PDF-`) beats extension sniffing for upload routing — already in place.
- `.env` and `docker-compose.yml` port drift is a common local-dev failure mode; the running container's actual port (via `docker ps`) is ground truth, not committed config.
- The CSV prompt already documents balance derivation from first/last transaction; the PDF prompt didn't inherit that — prompt parity across providers/formats matters when both target the same downstream schema.
- Failed script-gen attempts don't populate `bank_parser_scripts` cache, so prompt fixes take effect on the very next upload (no manual cache bust needed).
